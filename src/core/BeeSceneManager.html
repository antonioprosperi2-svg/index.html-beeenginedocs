BeeSceneManager — Documentazione Tecnica

Registro e dispatcher della scena corrente: add, change, update, draw. Nessuno stack.

📁 Panoramica

BeeSceneManager è il registro delle schermate e il puntatore alla scena attiva. Il motore la crea nel costruttore e la espone come engine.scenes. Tu registri oggetti-scena con add, passi da una all’altra con change, e il game loop chiama update / draw sulla corrente.

Quello che non è: uno stack (niente push/pop, niente overlay di pausa), un tween di transizione, un distruttore. Le scene restano nella Map finché non le sovrascrivi. change è un replace: esce la vecchia, entra la nuova, stesso oggetto se torni sullo stesso nome.

export class BeeSceneManager { constructor(engine) { this.engine = engine; this.ctx = engine.ctx; this.scenes = new Map(); this.currentScene = null; this.currentSceneName = null; } }

📁 Contratto di una scena (duck typing)

Non esiste una classe BeeScene obbligatoria. Qualsiasi oggetto va bene. Gli hook sono opzionali; se mancano, quel passo è un no-op. Se sulla stessa scena esistono sia onEnter sia enter, parte solo onEnter (stessa regola per onExit vs exit).

Hook / campo Quando Note reali
onEnter(data) / enter(data) Fine di change data è il secondo argomento di change, default null.
onExit() / exit() Inizio di change, se c’è già una corrente Nessun argomento. Non riceve la scena destinazione.
update(dt, input, engine) Ogni tick del manager Parte anche se dt <= 0. Poi il manager itera entities.
draw(ctx, engine) Ogni frame Poi il manager disegna le entity con engine.drawEntity.
entities Lista viva della scena Se manca, add / change la creano come [].

📁 add — registra, non avvia

add(name, scene) mette l’oggetto nella Map, assegna scene.engine = this.engine e, se scene.entities è falsy, lo inizializza a []. Non chiama enter. Un secondo add con lo stesso nome sovrascrive la voce nella mappa; se quella era la scena corrente, currentScene resta l’oggetto vecchio finché non fai di nuovo change.

scene nullo o non-oggetto: scene.entities lancia TypeError. Non c’è guardia.

game.scenes.add('menu', new BeeMenuScene()); game.scenes.add('game', livello); // a questo punto currentScene è ancora null: niente tick, niente draw

📁 change — replace, non stack

Ordine reale, se il nome esiste:

1. Se c’è una corrente → onExit oppure exit (senza data).

2. currentScene / currentSceneName puntano alla nuova. Copia anche su engine.currentScene (alias di compatibilità).

3. Re-inietta engine, assicura entities.

4. onEnter(data) oppure enter(data).

Nome assente → throw new Error('Scena non trovata: …'). Stesso nome della corrente: esce e rientra lo stesso oggetto. Utile per un restart se in onEnter riallochii le entity; se non le pulisci, le trovi ancora lì.

Non esiste push / pop. Un menu di pausa “sopra” il livello non è supportato: o sostituisci, o gestisci la pausa fuori da questa classe (engine.time.pause()).

game.scenes.change('game', { level: 3 }); // onExit della precedente (se c'era) → onEnter({ level: 3 }) game.scenes.change('game'); // di nuovo exit + enter sullo stesso oggetto; data = null

📁 Ciclo di vita nel loop: update poi draw

Il motore, se non è in pausa, chiama scenes.update(dt) e poi scenes.draw(ctx). Il secondo argomento che il loop passa a update (this.input) viene ignorato: il manager legge this.engine.input.

Dentro update, se non c’è scena corrente, esce. Altrimenti:

1. Hook della scena — scene.update(dt, engine.input, engine) parte sempre, anche con dt <= 0. È il ramo che tiene vivo un menu mentre il mondo è fermo, se qualcuno chiama il manager con dt zero.

2. Guardia dt — se dt <= 0 return: niente tick entity, niente filter.

3. Entity — per ciascuna, se active !== false e ha update, la chiama con la stessa terna (dt, input, engine).

4. Sweep — entities = entities.filter(e => !e.destroyed). Alloca un array nuovo ogni frame in cui il tick entity gira. Non chiama destroy() sulle entity: toglie solo quelle già marcate.

Pausa del motore. BeeEngine.loop non chiama affatto scenes.update quando time.paused è true. Il ramo “scena sì, entity no” del manager lo vedi solo se chiami scenes.update(0) tu, o se dt è zero senza passare da quella guardia del loop.

update(dt) { if (!this.currentScene) return; if (this.currentScene.update) { this.currentScene.update(dt, this.engine.input, this.engine); } if (dt <= 0) return; for (const entity of this.currentScene.entities) { if (entity.active !== false && entity.update) { entity.update(dt, this.engine.input, this.engine); } } this.currentScene.entities = this.currentScene.entities.filter( entity => !entity.destroyed ); }

draw(ctx = this.ctx): no-op senza scena. Poi scene.draw(ctx, engine) se esiste, poi per ogni voce di entities chiama engine.drawEntity (lì il motore salta visible === false e destroyed, e attraversa i children).

📁 Due liste di entity — non mescolarle

scenes.addEntity(entity) pusha su currentScene.entities, inietta entity.engine e entity.scene. Senza scena corrente è un return silenzioso. entity nullo → TypeError sul primo assegnamento.

engine.addEntity è un’altra lista: engine.entities. Il loop del motore aggiorna e disegna quella in parallelo. BeeEngine.setScene svuota engine.entities e physics, poi chiama scenes.change: non svuota scene.entities.

Se in scene.update / scene.draw iteri già this.entities, il manager le ritocca nello stesso frame: doppio update e doppio draw. Il demo in-tree cade in questa trappola. La regola pratica: o la scena possiede il loop, o lo lascia al manager. Non entrambi.

📁 change dentro update — cosa succede davvero

Se scene.update chiama change (come BeeMenuScene su Invio), in quello stesso tick onExit / onEnter sono già corsi. Il for sulle entity e il filter girano sulla nuova scena, non sulla vecchia. Le entity della scena appena uscita non ricevono un ultimo tick.

Se invece change parte da un entity.update, il for…of continua sull’array già aperto (quello vecchio); il filter finale è sulla scena nuova. Non è uno stack sicuro: è un replace a metà tick.

📁 Memoria, destroy, scene nulle

Non c’è remove, non c’è destroy sul manager. Uscire da una scena non azzera entities e non chiama entity.destroy(). Tornare su 'game' dopo il menu ritrova player, nemici e listener che c’erano, a meno che tu li pulisca in onExit o li riallochii in onEnter.

engine.destroy() ferma il loop e svuota engine.entities: non chiama onExit e non svuota la Map delle scene. I riferimenti scena → engine restano.

Senza scena corrente, update, draw e addEntity sono no-op. Non esiste start() sul manager: il “doppio start” è di BeeEngine.start() (se isRunning è già true, ritorna).

📁 Esempio: menu → livello, senza doppio tick

import { BeeEngine, BeeMenuScene, BeePlayer } from 'beeengine'; const game = new BeeEngine('game', 800, 600); const livello = { entities: [], onEnter(data) { this.entities = []; game.scenes.addEntity(new BeePlayer(80, 400)); // data?.level — payload di change(), o null }, onExit() { for (const e of this.entities) { if (e.destroy) e.destroy(); } this.entities = []; }, update(dt, input, engine) { // collisioni / win: NON iterare this.entities, lo fa il manager if (input.wasPressed('Escape')) engine.scenes.change('menu'); }, draw(ctx) { ctx.fillStyle = '#0d0f1a'; ctx.fillRect(0, 0, ctx.canvas.width, ctx.canvas.height); // NON ridisegnare le entity: ci pensa engine.drawEntity } }; game.scenes.add('menu', new BeeMenuScene()); game.scenes.add('game', livello); game.scenes.change('menu'); game.start();

📁 Note per chi integra

Scegli un solo owner del loop entity. O scene.update/draw le scorrono, o lo fa il manager. Il secondo passaggio non è un opt-in: è sempre acceso se dt > 0.

Pulisci in exit/enter. Il replace non è un teardown. Listener, collision groups, musica e entities sopravvivono al cambio di schermata.

Non usare engine.addEntity per oggetti di scena se ti aspetti che spariscano con change. Quella lista è del motore, e setScene la svuota senza toccare la lista della scena.

Nessuna transizione. Fade, wipe, load async: tu, prima di change o dentro onEnter. Il manager è sincrono e immediato.

📁 Riepilogo API

Membro Ritorna Scopo
constructor(engine) BeeSceneManager Salva engine e engine.ctx. Map vuota, corrente null.
scenes Map Registro vivo nome → oggetto scena.
currentScene object | null Oggetto attivo, o null prima del primo change.
currentSceneName string | null Chiave nella Map della corrente.
add(name, scene) void Registra. Inietta engine, crea entities se manca. Non entra.
change(name, data = null) void Replace: exit → swap → enter. Throw se il nome non è in mappa.
addEntity(entity) void Push su currentScene.entities. No-op senza scena. Non tocca engine.entities.
update(dt) void Hook scena, poi (se dt > 0) tick entity e filter destroyed.
draw(ctx = this.ctx) void Hook scena, poi engine.drawEntity su ogni entity.
getCurrentScene() object | null Alias di currentScene.
getCurrentSceneName() string | null Alias di currentSceneName.
